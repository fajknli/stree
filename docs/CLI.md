# stree CLI 与协议参考手册

本文档是 `stree` 引擎与外部业务层（胶水脚本）之间的严格契约。任何偏离这些规范的行为都可能导致未定义的结果。

---

## 1. 数据协议

### 1.1 实体数据流 (stdin)

引擎从标准输入读取制表符分隔值（TSV）流。每一非空行必须严格包含 4 个字段：

```text
ID \t Display \t Path \t Tags
```

#### 字段规范

| 字段 | 约束条件 | 引擎行为 |
| :--- | :--- | :--- |
| **ID** | 非空字符串。在流内必须全局唯一。 | 用作树形关联、选中状态记忆和 IPC 定位的主键。重复的 ID 会被去重（保留最后一次出现的）。 |
| **Display** | 任意 UTF-8 字符串。 | 在树形列表中逐字渲染。引擎不解析也不解释其内容。 |
| **Path** | 任意 UTF-8 字符串。 | 视为不透明的业务负载。通过 `{path}` 占位符原样传递给外部命令。当展开为 `{paths}` 时，路径内部的双引号会被自动转义。 |
| **Tags** | 逗号分隔的标签列表（如 `live,note,inbox`）。 | 按 `,` 拆分，去除首尾空白，并过滤掉空标签。供样式引擎匹配和业务层状态过滤使用。 |

#### 防御性解析规则

为了确保对外部脚本脏数据的鲁棒性，引擎强制执行以下规则：
1.  **强制 Trim**：每个字段的前导/尾随空白符和回车符（`\r`）会被剥离。
2.  **空 ID 拒绝**：`ID` 字段为空的行会被静默跳过（并向 stderr 输出警告）。
3.  **字段数检查**：少于 4 个字段的行会被静默跳过。
4.  **版本头（可选）**：如果第一行的第一个字段以 `VERSION:` 开头，引擎会解析版本号，并从第二个字段开始作为 ID 处理。

    --relations 文件不会被引擎自动监控。如果你修改了它的内容，必须同时通过 IPC 推送 Tree 数据（stree update 窗口名），否则树形结构不会更新。引擎只在 Tree 窗口刷新时才会重新读取该文件。

### 1.2 关联表 (`--relations <file>`)

一个 2 列的 TSV 文件，用于定义父子关系：

```text
Parent_ID \t Child_ID
```

*   **树构建**：引擎在内存中构建离散的树形拓扑。任何未在任何关系中作为子节点出现的 ID，都会自动成为根节点。
*   **排序**：根节点按字母顺序排序。节点内部的子节点保留其在关联文件中出现的顺序。
*   **环容忍**：引擎不执行 DAG 环检测。循环关系会导致未定义的渲染行为（业务层有责任确保无环）。

### 重载时关系表加载规则
当执行初始启动、IPC `stree update Files`、SIGUSR1 重载时：
1. 若启动参数携带 `--relations <path>`：
   引擎每次重新读取该磁盘文件解析父子关系；文件不存在/格式损坏则使用空关系表，丢弃内存中原有拓扑。
2. 若未携带 `--relations` 参数：
   直接复用内存中上次加载完成的父子关系，不会从磁盘重新读取任何关系文件。

### IPC update 联动说明
`stree update Files` 会完整重新执行 `--tree` 绑定的数据源命令，并同步重新加载 --relations 文件，实现树形实体与父子关系同步刷新。

## 2. IPC 二进制协议

引擎暴露一个 Unix Domain Socket 用于定向的局部更新。Socket 路径通过环境变量 `$STREE_SOCK` 暴露。

### 2.1 二进制帧格式

客户端必须发送如下结构的二进制帧（所有整数均为**大端序 Big-Endian**）：

| 偏移量 | 大小 | 字段 | 描述 |
| :--- | :--- | :--- | :--- |
| 0 | 4 字节 | `target_len` | 目标窗口名的长度 (u32)。最大：128 字节。 |
| 4 | 8 字节 | `data_len` | 负载数据的长度 (u64)。最大：512 KB。 |
| 12 | `target_len` | `target` | UTF-8 编码的窗口名（如 `MainTree`, `Preview`）。 |
| 12+N | `data_len` | `data` | UTF-8 编码的负载（Tree 为 TSV，View/StatusBar 为纯文本）。 |

### 2.2 响应

处理成功后，引擎回复 ASCII 字符串 `OK`。如果帧格式错误（如超出大小限制），引擎回复 `ERROR: ...` 字符串并关闭连接。

### 2.3 CLI 客户端

引擎二进制文件本身兼作 IPC 客户端：

```bash
# 将 TSV 数据推送到 Tree 窗口（触发重新解析和局部重绘）
./generate-data.sh | stree update MainTree

# 将纯文本推送到 View 窗口（替换内容缓冲区）
echo "Loading..." | stree update Preview

# 将文本推送到 StatusBar 窗口（替换格式模板的输出）
echo "Custom Status" | stree update Status
```

### 2.4 各组件类型的语义

*   **Tree**：负载必须是合法的 4 列 TSV 流。引擎重新解析它，重建树，在可能的情况下保留展开/选中状态，如果该树当前处于焦点状态，则触发 `broadcast_selection_changed`。
*   **View**：负载被视为原始文本。`cached_entity_id` 会被失效，以强制在下一次选中状态改变时刷新。
*   **StatusBar**：负载替换渲染的文本（绕过格式模板）。

## 3. 布局语法与分配规则

`--layout` 字符串定义空间拓扑。引擎使用类似 Flexbox 的分配算法。

### 3.1 节点语法

```text
area(size)[border]:Name
```

*   **`size`**：
    *   `50%` ：剩余空间的百分比（在扣除绝对尺寸之后）。
    *   `3` ：绝对尺寸（垂直容器为行数，水平容器为列数）。
    *   *(留空)* ：参与剩余空间的均分。
*   **`border`**：`box`（默认）、`line`（单顶线）、`none`（无边框）。
*   **`Name`**：用于组件挂载的唯一标识符。

### 3.2 分配算法（严格顺序）

对于总长度为 `L`（宽度或高度）的容器：

1.  **扣除绝对值**：累加所有具有绝对尺寸的子节点（`A`）。剩余空间 `R = L - A`。
2.  **计算百分比**：
    *   如果 `未声明尺寸的节点数 > 0` 且 `百分比总和 <= 100`：每个百分比节点获得 `R * (pct / 100)`。剩余空间在未声明尺寸的节点间均分。
    *   如果 `百分比总和 > 100` 或 `未声明尺寸的节点数 == 0`：每个百分比节点获得 `R * (pct / 百分比总和)`。这确保了即使声明了 200% 的总和，容器也总是被填满。
3.  **整数余数**：由于整数除法，可能会出现像素缝隙。引擎会将余数加到**最后一个有效的 flex 节点**上，以消除视觉缝隙。

### 3.3 边界情况

*   **百分比总和 > 100**：节点被等比例压缩以适应容器。
*   **百分比总和 < 100（有未声明节点）**：未声明节点均分吸收剩余空间。
*   **百分比总和 < 100（无未声明节点）**：所有百分比节点被等比例拉伸以填满容器。
*   **绝对值总和 > 总长度**：绝对值节点通过 `saturating_sub` 被截断，flex 节点获得 0 尺寸。

## 4. 执行模型 (`--bind`)

### 4.1 默认模式（全屏）

```bash
--bind "enter=vi {path}"
```

1.  引擎禁用原始模式（raw mode），离开备用屏幕（Alternate Screen），释放鼠标捕获。
2.  TTY (`/dev/tty`) 被克隆并附加到子进程的 stdin/stdout/stderr。
3.  引擎阻塞在 `child.wait()` 上。
4.  退出后，引擎排空挂起的输入事件（最多 100 个），重新进入备用屏幕，并触发 `trigger_reload`（重新执行所有 `--tree` 的数据源命令）。

### 4.2 静默模式（`@` 前缀）

```bash
--bind "ctrl-t=@switch-view.sh"
```

1.  引擎**保留** TUI 状态（无屏幕闪烁）。
2.  子进程以 `stdin=null`, `stdout=null`, `stderr=null` 启动。
3.  引擎调用 `.status()` 而不是 `.output()`。这是一个**关键的防御措施**：它防止了后台任务（`&`）继承管道文件描述符而导致的死锁。
4.  引擎排空挂起的输入事件。
5.  **不会自动重载**。业务脚本完全负责通过 IPC (`stree update`) 推送更新。

### 4.3 占位符展开

占位符在命令被拆分为参数**之前**进行展开。

| 占位符 | 展开规则 |
| :--- | :--- |
| `{id}` | 选中节点的 ID。若无则空字符串。 |
| `{path}` | 选中节点的 Path。若无则空字符串。 |
| `{ids}` | 所有被标记节点的 ID 列表（空格分隔）。若无标记则回退到 `{id}`。 |
| `{paths}` | 所有被标记节点的 Path 列表，每个 Path 用双引号包裹，内部引号被转义。 |
| `{window}` | 当前焦点窗口的名称。 |
| `{width}` | 在 `--view` 中：View 窗口的内部宽度。在 `--bind` 中：终端总宽度。 |
| `{height}` | 在 `--view` 中：View 窗口的内部高度。在 `--bind` 中：终端总高度。 |

## 5. 样式引擎 (`--status-col`)

### 5.1 语法

```bash
--status-col "pattern1=style1,pattern2=style2,..."
```

*   **分隔符**：规则由逗号分隔。然而，由于样式本身可以包含逗号（如 `red,bold`），解析器使用**从右向左**的启发式规则：它查找下一个 `=` 之前的最后一个逗号，以将样式与下一个模式分开。
*   **模式 (Pattern)**：
    *   精确字符串：`live`
    *   正则表达式：`^fail.*`（通过存在 `^`, `*`, `.`, `+`, `?`, `[` 来检测）
*   **样式 (Style)**：`color` 和/或 `bold` 的逗号分隔列表。
    *   颜色：`black`, `red`, `green`, `yellow`, `blue`, `magenta`, `cyan`, `white`, `gray`/`grey`/`darkgray`/`darkgrey`。

### 5.2 匹配语义（标签集）

引擎按逗号拆分节点的第 4 列（Tags）。对于每条规则，它检查标签集中是否**有任何一个**标签匹配该模式。

*   **颜色覆盖**：后匹配的规则覆盖先匹配的规则。
*   **加粗累加**：如果任何匹配的规则指定了 `bold`，最终结果即为加粗。

**示例**：
```bash
--status-col "live=white,archived=gray,note=blue,inbox=cyan,^fail.*=red,bold"
```
对于一个 Tags 为 `note,archived,inbox` 的节点：
1.  `note=blue` 匹配 -> 颜色变为蓝色。
2.  `archived=gray` 匹配 -> 颜色变为灰色（覆盖蓝色）。
3.  `inbox=cyan` 匹配 -> 颜色变为青色（覆盖灰色）。
**最终结果**：青色文本。

## 6. 信号处理

| 信号 | 行为 |
| :--- | :--- |
| `SIGUSR1` | 触发 `trigger_reload`：重新执行每个 `--tree` 组件的数据源命令，并在内部通过 IPC 更新其数据。 |
| `SIGINT` (Ctrl-C) | 发起优雅关闭。引擎清理 socket 文件，恢复终端状态，并退出。 |

---

## 7. 退出行为

在优雅退出时（通过 `q` 或 `Esc`），引擎会将**最终选中节点的 ID** 输出到标准输出，后跟一个换行符。这允许 shell 包装器捕获用户的选择：

```bash
selected=$(my-data.sh | stree --tree "Main")
echo "User selected: $selected"
```

如果引擎崩溃或被未处理的信号杀死，panic hook 会确保终端状态（raw mode, alternate screen, 鼠标捕获）被恢复，并且 socket 文件被删除。

## 8. 环境变量

| 变量 | 作用域 | 描述 |
| :--- | :--- | :--- |
| `$STREE_SOCK` | 子进程 | Unix Domain Socket 的绝对路径。由引擎在生成任何子进程之前设置。仅在引擎进程的生命周期内有效。 |
| `$FORCE_COLOR` | 子进程 | 引擎在生成 `--view` 命令时设置为 `1`，强制 `bat` 或 `ls` 等工具输出颜色。 |
| `$CLICOLOR_FORCE` | 子进程 | 设置为 `1`，用于 BSD 风格的颜色强制。 |
| `$TERM` | 子进程 | 设置为 `xterm-256color` 以确保最大的颜色兼容性。 |
